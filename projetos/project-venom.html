🐍 PROJECT VENOM

Honeypot HTTP para observação de requisições

Um laboratório de segurança desenvolvido em JavaScript com Node.js para receber requisições HTTP, registrar endereços de origem e caminhos acessados e observar tentativas de interação com um serviço simulado.

VISÃO GERAL

Sobre o projeto

O PROJECT VENOM é um honeypot experimental que simula um serviço HTTP protegido. A aplicação recebe as requisições direcionadas ao servidor e registra informações úteis para observação e análise.

A proposta é praticar conceitos de monitoramento, registro de eventos, análise de requisições e identificação de padrões de acesso em um ambiente controlado.

FLUXO DE FUNCIONAMENTO

Como funciona

01. Escuta HTTP

O servidor Node.js recebe requisições na porta 3000.

02. Registro

Captura o endereço remoto e a rota solicitada, acompanhados de data e hora em UTC.

03. Resposta simulada

Retorna o status HTTP 401 Unauthorized para as requisições recebidas.

04. Auditoria local

Grava os eventos em logs/venom.log e exibe alertas no terminal.

IMPLEMENTAÇÃO

Componentes e tecnologias

Servidor HTTP: módulo nativo http do Node.js para receber conexões e responder às requisições.

Registro de eventos: módulos fs e path para gravar os dados em arquivo local.

JavaScript: lógica principal de tratamento das requisições e geração dos registros.

Python: script auxiliar experimental para registrar a inicialização do projeto.

Ambiente: Linux / WSL Ubuntu, terminal, Git e GitHub.

APRENDIZADO PRÁTICO

Conceitos aplicados

Honeypots • HTTP • Endereços IP • Logs • Monitoramento • Node.js • Linux • Auditoria de requisições

O projeto permite observar os dados básicos de cada acesso e utilizar os registros como ponto de partida para exercícios de análise e investigação defensiva.

TRANSPARÊNCIA TÉCNICA

Escopo e limitações

O PROJECT VENOM é um honeypot simples, desenvolvido para fins educacionais e execução em laboratório. A implementação atual registra o endereço remoto e a rota HTTP, mas não realiza identificação de pessoas, atribuição de autoria ou análise automatizada de ameaças.

A resposta HTTP 401 é uma resposta simulada do serviço; ela não representa, por si só, uma detecção ou bloqueio de invasão. Os registros devem ser interpretados considerando o contexto do ambiente e possíveis acessos legítimos.

Não é uma solução de produção. Antes de qualquer exposição externa, são necessários controles adicionais de segurança, validação de entradas, proteção dos registros e isolamento adequado do ambiente.
