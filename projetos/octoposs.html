🐙 OCTOPOSS

Blue Team Evidence Center

VISÃO GERAL

Sobre o projeto

O OCTOPOSS é um laboratório defensivo criado para transformar informações técnicas do sistema em elementos que apoiem análise e investigação de segurança.

Seu princípio é Evidence First: uma anomalia não é automaticamente considerada uma ameaça. As evidências disponíveis são analisadas e correlacionadas antes de qualquer conclusão.

FLUXO DE ANÁLISE

Como funciona

O fluxo organiza as etapas de análise defensiva.

01. Coleta

Levantamento de processos, serviços, sockets, logs e informações do sistema.

02. Correlação

Busca por relações entre processos, serviços, conexões e eventos registrados.

03. Classificação

Organização dos resultados em relações confirmadas, parciais ou insuficientes.

04. Investigação

Registro de situações que precisam de análise complementar, sem presumir atividade maliciosa.

ARQUITETURA

Componentes principais

Collector: coleta informações do ambiente Linux, incluindo processos, serviços, sockets e registros do sistema.

Correlator V07: aplica regras para relacionar evidências e classificar os resultados da análise.

Central Mind: núcleo que recebe informações dos componentes e mantém o estado das correlações e investigações.

Central Bridge: integra o correlator ao núcleo central.

Evidence Center: interface web com dashboard e endpoints para consulta de inventário, relatório, evidências e painel.

TECNOLOGIAS

Stack utilizada

Python • JavaScript • HTML5 • CSS3 • Linux / WSL • APIs HTTP • Git • GitHub

Práticas aplicadas: coleta de dados, análise de logs, correlação de eventos, investigação defensiva e documentação técnica.

TRANSPARÊNCIA TÉCNICA

Escopo e limitações

O OCTOPOSS é um projeto de laboratório e demonstração técnica, não uma plataforma SIEM ou solução de monitoramento de produção. Seu mecanismo de correlação é baseado em regras, não em inteligência artificial ou aprendizado de máquina.

Algumas relações podem permanecer parciais ou insuficientes quando os dados coletados não permitem atribuir, por exemplo, um socket diretamente a um processo. Nesses casos, o projeto preserva a incerteza e sinaliza a necessidade de investigação.

As evidências locais do ambiente de laboratório são mantidas fora do repositório público para evitar a exposição de dados do sistema.
